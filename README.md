# ESP32-C3 WebUI

**واجهة ويب وخادم HTTP غير متزامن لبوردة ESP32-C3، مع تسجيل دخول وإعدادات واي فاي ومدير ملفات للطوارئ.**

</div>

---

## المميزات

- **خادم غير متزامن** (ESPAsyncWebServer) يقدّم واجهتك من `/app/index.html` على LittleFS.
- **تسجيل دخول بدورين:** `admin` و`user`، مع رمز (Token) يُولَّد عند كل دخول.
- **إعدادات محفوظة في JSON** على LittleFS: الواي فاي، عناوين الاتصال، رمز PIN، وكلمات المرور.
- **أوضاع واي فاي:** `AP` و`STA` و`AP_STA`، مع **وضع استرداد** (`RECOVERY_MODE`) إذا فشل الاتصال بالشبكة في وضع STA.
- **مدير ملفات للطوارئ** على المسار `/em`: عرض، رفع، تحميل، تعديل، إعادة تسمية، حذف، وتهيئة الذاكرة.
- **مراقبة الموارد:** نسبة استخدام الذاكرة (RAM) والتخزين عبر `/hdusage`.

## المتطلبات

| العنصر | القيمة |
|---|---|
| اللوحة | `esp32-c3-devkitm-1` |
| الإطار | Arduino عبر PlatformIO |
| نظام الملفات | LittleFS |
| المكتبات | ArduinoJson ^7، ESPAsyncWebServer 3.6.0، AsyncTCP 3.3.2 |

## الواجهة (Svelte)

الواجهة مكتوبة بـ Svelte + Vite في المجلد `ui/`، وتُبنى إلى ملف واحد مضغوط `data/app/index.html.gz` (بضع عشرات من الكيلوبايت).

```
cd ui
npm install
npm run build        # الناتج: data/app/index.html.gz
pio run -t uploadfs  # من جذر المشروع: رفع الواجهة إلى LittleFS
```

للتطوير مع اللوحة مباشرة: `ESP_IP=192.168.4.1 npm run dev`. أما في GitHub Actions فتُبنى الواجهة تلقائيًا ويُرفق `littlefs.bin` مع كل إصدار.

## التحديث عبر الشبكة (OTA)

من الواجهة: تبويب **تحديث** (للـ admin) ثم اختر `firmware-*.bin` لتحديث البرنامج، أو `littlefs-*.bin` لتحديث الواجهة. الملفات في صفحة الإصدارات. بعد التحديث يُعاد تشغيل الجهاز تلقائيًا.

> ويمكن تحديث الواجهة أيضًا من صفحة الطوارئ `/em` (زر **تحديث الواجهة**) إذا فُقدت الواجهة.

> تحديث الواجهة (littlefs) يمسح الإعدادات وكلمات المرور. تحديث البرنامج (firmware) لا يمسحها.

المسار: `POST /api/ota?type=fw|fs` برمز admin (أو مفتاح الطوارئ لـ `type=fs` فقط) وجسم `multipart/form-data` بحقل `file`.

## النسخ الاحتياطي

تبويب **نسخ احتياطي** (للـ admin): تنزيل ملف JSON فيه الإعدادات وكلمات المرور، واستعادته لاحقًا (يُعاد تشغيل الجهاز بعدها). مفيد قبل تحديث الواجهة (littlefs) لأنه يمسح الإعدادات. المساران: `GET /settings/backup` و`POST /settings/restore`. الملف يحتوي كلمات المرور كنص صريح.

## التشغيل

1. افتح المشروع في PlatformIO ثم نفّذ **Build** و**Upload**.
2. ابنِ الواجهة (انظر قسم الواجهة) ثم نفّذ **Upload Filesystem Image**.
3. اتصل بشبكة الـ AP الافتراضية، واسمها `ESP32_AP` وكلمة المرور `12345678`.
4. افتح `http://192.168.4.1/` للواجهة. وإذا لم يوجد `/app/index.html` (أول تشغيل أو فُقد الملف) تظهر **نافذة إدخال المفتاح السري** للدخول إلى مدير الملفات `/em`، ومنه ترفع الواجهة.

## البيانات الافتراضية

> **غيّرها قبل أي استعمال حقيقي.**

| العنصر | القيمة الافتراضية |
|---|---|
| مستخدم admin | `admin` / `admin123` |
| مستخدم user | `user` / `user123` |
| مفتاح الطوارئ `/em` | `1234` (الثابت `access_key` في `main.cpp`) |
| شبكة AP | `ESP32_AP` / `12345678` |
| شبكة الاسترداد | `RECOVERY_MODE` / `12345678` |

## واجهة البرمجة (API)

يُرسَل الرمز في الترويسة `User_Token`، ويُرسَل الدور في `User_Role` إن لزم.

| المسار | الطريقة | الصلاحية |
|---|---|---|
| `/login` | POST | عامة، جسمها `{"username","password"}` |
| `/hdusage` | GET | أي رمز صالح |
| `/settings/get_comm` ، `/settings/get_pin` | GET | أي رمز صالح |
| `/settings/get_wifi` ، `/settings/get_pass` | GET | admin |
| `/settings/get_stat` ، `/settings/scan_wifi` | GET | عامة |
| `/settings/save_wifi` ، `save_comm` ، `save_pin` ، `save_pass` | POST | admin |
| `/api/*` (مدير الملفات) | متعددة | رمز admin أو مفتاح الطوارئ |

حفظ إعدادات الواي فاي يردّ بـ `200` فورًا، ثم تُطبَّق الإعدادات بعد لحظات، وقد ينقطع الاتصال أثناء ذلك.

## ملاحظات أمنية

- نافذة المفتاح تقفل المحاولات دقيقة واحدة بعد 5 محاولات خاطئة (`/em/check`).
- مفتاح الطوارئ ما زال مقبولًا في الرابط (`?pass=`) ويُخزَّن في كوكي، فاعتبره حماية أولية فقط.
- لا تتصل بالشبكات المفتوحة وأنت تستعمل الإعدادات الافتراضية.
- الرموز لا تنتهي صلاحيتها، وكل تسجيل دخول يبطل الرمز السابق لنفس الدور.
