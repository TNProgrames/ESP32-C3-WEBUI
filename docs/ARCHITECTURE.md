# بنية المشروع: ثلاث طبقات وعقد واحد

الهدف: تعديل سلوك التطبيق **دون إعادة ترجمة الفيرموير**، وأن يستطيع أي شخص كتابة درايفر أو سكريبت أو اختبار من الواجهة لأي جهاز، بكود قصير واضح وبلا دوال خاصة بكل جهاز.

```
┌──────────────────────────────────────────────────────────┐
│ 3. التطبيق      سكريبتات Lua  (/scripts/*.lua)            │  تتغير بلا ترجمة
│    المنطق · الأحداث · الواجهة · timer.every              │
├──────────────────────────────────────────────────────────┤
│ 2. الربط (HAL)  الفيرموير: drv.open + التحقق + خدمات     │  يتغير بتحديث الفيرموير
│    يحوّل استدعاء Lua إلى استدعاء درايفر بعد فحصه          │
├──────────────────────────────────────────────────────────┤
│ 1. الدرايفر     كود C موقّع (/drivers/*.drv) + خدمات نظام│  يُثبَّت أو يُحدَّث وحده
│    العتاد والبروتوكولات فقط                              │
└──────────────────────────────────────────────────────────┘
```

كل طبقة تكلّم التي تحتها فقط. الدرايفر لا يعرف Lua، وLua لا يلمس العتاد الخام.

## الطبقة 1: العتاد

### أ) درايفرات قابلة للتحميل (`.drv`)
شاشات وحساسات ومحوّلات صوت. كود C مجمَّع وموقَّع يُحمَّل عند الإقلاع. مواصفاته في [scripting/drivers.md](scripting/drivers.md).

قواعد كتابتها:
- **العتاد عبر جدول `drv_api_t` فقط** (I2C وSPI وتوقيت وذاكرة). لا استدعاء مباشر لمكتبات الفيرموير.
- **لا تخصيص ذاكرة داخل الحلقات السريعة.** `alloc` مرة واحدة في `open`، و`release` في `close`.
- **لا انتظار طويل.** `delay_ms` للتهيئة فقط (عشرات الملّي ثانية)، والنقل الكبير يُقسَّم أو يتم بـDMA.
- لا float، ولا معرفة بـLua أو بالواجهة.

### ب) خدمات النظام (داخل الفيرموير)
Wi-Fi وBLE وGPIO وADC وPWM. تعتمد على مكدسات ESP-IDF الكبيرة والمقاطعات فلا تصلح للتحميل. تُقدَّم لـLua بوحدات مثل `gpio` و`adc` و`pwm`، وليست درايفرات.

## الطبقة 2: العقد الموحّد

الدرايفر **يصف نفسه** بجدول دوال، والفيرموير يستخرج منه كل شيء: التحقق والربط بـLua ونموذج الاختبار في الواجهة.

```c
// حرف لكل معامل:  i = عدد صحيح   s = نص   b = منطقي   d = بيانات خام
static const drv_method_t METHODS[] = {
  { "text",  "iis", do_text  },   // (صف، عمود، نص)
  { "clear", "",    do_clear },
};
```

الدرايفر كله ثلاثة أشياء: `open` (يقرأ الإعداد ويهيّئ) و`close` (يحرر) وجدول الدوال. ملف `drivers/lcd1602/lcd1602.c` هو القالب.

ما يفعله الفيرموير قبل استدعاء الدالة:
1. يتأكد أن الدالة موجودة في الجدول.
2. يطابق عدد المعاملات وأنواعها مع سلسلة الأحرف.
3. يرفض النص أو البيانات الأكبر من الحد.
4. يستدعيها ويحوّل القيم المعادة إلى Lua.

فلا يحتاج كاتب الدرايفر إلى كود تحقق من الأنواع، ولا يسبب سكريبت Lua انهيارًا بمعاملات خاطئة. أما حدود القيم (إحداثيات الشاشة ومجال القياس) فيتحقق منها الدرايفر نفسه ويعيد `DRV_E_ARGS`.

### اتفاقيات الأسماء (توثيق لا كود)
| الفئة | الدوال المعتادة |
|---|---|
| شاشة | `clear` `text(row,col,str)` أو `text(x,y,str)` · `rect` · `line` · `show` |
| حساس | `read()` ترجع القياسات بالترتيب الموثَّق |
| صوت | `play(data)` · `stop()` · `volume(n)` |
| عام | `info()` ترجع الاسم والإصدار |

الدرايفر الجديد يلتزم بالاتفاقية ما أمكن ليسهل تبديله، لكنها غير مفروضة بكود.

## الطبقة 3: سكريبت Lua

صيغة واحدة لكل الأجهزة:

```lua
local d, err = drv.open("lcd1602", {addr = 0x27})   -- الاسم + الإعداد
if not d then print(err) return end
d:text(0, 0, "Hello")                                -- اسم الدالة + المعاملات
```

- المنطق والأحداث في `timer.every` و`gpio.on_change` و`bus.subscribe` و`ui.on`، بلا حلقات انتظار (الحارس يوقف أي سكريبت يعلق أكثر من 200ms).
- الأخطاء تعود قيمًا: `nil, "bad_args"` أو `"unknown_method"` أو `"device_error"`، ولا تنهار.
- يُغلق الدرايفر تلقائيًا عند إيقاف السكريبت.

## تدفق البيانات

**من العتاد إلى Lua:** حساس ← الدرايفر يقرأ بالبروتوكول ← يعيد `drv_val_t` أعدادًا صحيحة ← الربط يحوّلها لقيم Lua ← السكريبت يحسب ويعرض بـ`ui`.

**من Lua إلى العتاد:** السكريبت ينادي `d:text(...)` ← الربط يتحقق من النوع والحجم ← الدرايفر يرسل الأوامر.

**البيانات الكبيرة (صورة، صوت):** يمرّرها Lua كنص بايتات (`d`) بمرجع دون نسخ داخل الاستدعاء، والدرايفر يرسلها بالـDMA على دفعات. وللصوت تُغذّى ذاكرة حلقية داخل الدرايفر وتقرؤها مهمة بث، فلا تمر العينات على Lua واحدة واحدة.

## الذاكرة والتوقيت (ESP32-C3)

- نحو 270KB متاحة للتطبيق. لكل سكريبت 48KB، وكل درايفر 2–10KB، وBLE يحتاج 60–80KB حين يُفعَّل.
- **الشاشات الملونة:** لا إطار كامل. شاشة 128×160 بـ16 بت = 40KB، لذا يرسم الدرايفر **أشرطة** صغيرة ويبثها بالـDMA. شاشات أكبر تُرسم مباشرة بلا إطار وسيط.
- **التحديث:** السكريبت يحدّث كل 50–1000ms بحسب الحاجة، والدرايفر يرسل الجزء المتغير فقط.
- **توقيت دقيق** (WS2812 وDHT وIR): في الدرايفر أو خدمة RMT، لا في Lua.

## الواجهة (الويب)

تبويب «درايفرات» يقرأ جدول دوال كل درايفر مثبّت ويبني نموذجًا تلقائيًا: حقل لكل معامل وزر استدعاء ومنطقة نتيجة. فيمكن اختبار أي درايفر جديد دون كتابة واجهة له. صفحات مخصصة (`ui.panel` و`p:page`) تبقى لمن يريد واجهة تطبيقية.

## فصل الأعطال

- درايفر موقّع فقط يُحمَّل، وأي بايت معدّل يُرفض.
- انهيار أثناء تحميل درايفر يُحجره في الإقلاع التالي.
- حدود الذاكرة والوقت لكل سكريبت، وإيقاف السكريبت المعلّق بالحارس.
- العدّاد `.boot` يوقف التشغيل التلقائي عند تكرار الانهيار.

## كيف أضيف جهازًا؟

1. انسخ `drivers/lcd1602/` باسم جهازك.
2. عدّل `open` (قراءة الإعداد وتهيئة الجهاز) وجدول الدوال.
3. `python3 tools/drv/build_drv.py drivers/<name>` ثم `python3 tools/drv/test_emu.py` للتجربة على الحاسوب.
4. ارفع الملف من تبويب «درايفرات» واستدعه من Lua بـ`drv.open`.
